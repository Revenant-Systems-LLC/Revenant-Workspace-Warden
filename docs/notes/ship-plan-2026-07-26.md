### 1.6 The licence system works, and ships a keygen (historical: replaced by signed keys)

> **Replaced on 2026-10-20; see `license-signing-2026-10-20.md`.** Keys are now ECDSA P-256
> signatures checked against a public key embedded in the client, so the binary holds nothing that
> can mint a key: `_secret`, the HMAC check and `GenerateProKey()` are gone. Item 2 below was half
> right. A hardcoded secret is unavoidable only for a symmetric scheme like HMAC; offline validation
> against a public key needs none. Offline checks can still be patched out of the binary. The rest
> of this section describes the code as it was on 2026-07-26.

`Providers/LicenseManager.cs`. HMAC-SHA256, 12-byte key, `WARD-XXXXXXXX-XXXXXXXX-XXXXXXXX`.
Byte 0 is tier, bytes 1-5 random, bytes 6-11 the first 6 bytes of the HMAC. Local storage is
AES-CBC encrypted under `SHA256("RWW-" + MachineName + "-v1")`. Gates Tutor, Quiz and the Sidekick
scan at `MainWindow.xaml.cs:719, 836, 865, 1152, 1289`. The validation logic is correct and it works.

Three problems, in order of how much they matter:

1. **`GenerateProKey()` is a public static method compiled into the shipped binary**
   (`LicenseManager.cs:79-88`). That is not "the secret is extractable", that is a working
   keygen distributed inside the product, callable by reflection in one line.
2. **The signing secret is hardcoded** at `LicenseManager.cs:18-24`. Unavoidable for offline
   validation; every offline scheme is crackable. Worth 30 minutes, not more.
3. **`README.md:96` says licences "bind to the machine". They do not.** `GetMachineKey()` only
   derives an AES key for the local `license.dat`. The key itself validates on any machine, is not
   tied to a buyer or an email, and cannot be revoked. One key posted to a forum works for everyone.
   That sentence must not appear on the sales page.

`Revenant-Theme-Studio/Services/LicenseService.cs` is the identical algorithm with a different
secret and an `RTSP-` prefix. Reusing it server-side is correct; both products can share one
minting endpoint with a per-product secret and prefix.

### Step 6 — The Release build (2.5 h)

**The exact command:**

```powershell
dotnet publish M:\Projects\Revenant-Workspace-Warden\RevenantWorkspaceWarden.csproj `
  -c Release `
  -r win-x64 `
  --self-contained true `
  -p:PublishSingleFile=false `
  -p:DebugType=none `
  -p:SatelliteResourceLanguages=en `
  -o M:\Projects\Revenant-Workspace-Warden\dist\warden-1.0.0-win-x64
```

Why each flag:

- `--self-contained true` — the alternative is a 15 MB download that dies on any machine without
  the .NET 10 Desktop Runtime. .NET 10 shipped recently; almost no consumer box has it. A
  "download this other thing first" step at install time is a conversion killer. Pay the size.
- `PublishSingleFile=false` — **do not use single-file here.** Tesseract 5.2.0 probes for its
  native `leptonica` and `tesseract` DLLs in `x64\` and `x86\` subfolders relative to the app
  directory. Single-file extraction flattens that layout and OCR breaks. Theme Studio gets away
  with single-file; Warden will not.
- `DebugType=none` — no `.pdb` in the customer package.
- `SatelliteResourceLanguages=en` — drops the 14 localisation folders that Roslyn drags in
  (`cs`, `de`, `es`, `fr`, `it`, `ja`, `ko`, `pl`, `pt-BR`, `ru`, `tr`, `zh-Hans`, `zh-Hant`).
- `-o <fresh dated folder>` — this is what excludes `ggml-medium.en.bin`. Publish somewhere new
  every time; never reuse a folder, never package from `bin/`.

Budget most of the 2.5 h for the **first Release build of a 3,465-line WPF project that has only
ever been built Debug**. Expect nullable warnings promoted to problems, XAML resource issues, and
at least one asset that resolved in Debug and does not in Release.

### Step 10 — How a licence key reaches a buyer (3.0 h, or 0 h — read the fork)

> **Updated 2026-10-20 for signed keys; see `license-signing-2026-10-20.md`.** A key is now an
> ECDSA P-256 signature (format v2, 139 characters), minted with a private key that never enters the
> client or any repo. Both paths below changed; the reasoning for the fork did not.

**Recommended for launch week: manual.** Stripe emails you on every sale. Mint a key on Yggdrasil
with the private key you generated with `WardenKeyMint keygen`:

```powershell
dotnet run --project M:\Projects\Revenant-Workspace-Warden\tools\WardenKeyMint -- mint "<path to warden-license-1.pem>"
```

Paste it into a reply. Under two minutes per sale. At zero historical sales this is not a
bottleneck, and it means you are not debugging a new PHP endpoint on the same day you are debugging
a new build. Set the redirect to a static `thanks.html` that says *"Your key is on its way to the
email you paid with, usually within a few hours."* Then honour that.

**The automated version, when volume justifies it:** `public_html/warden-pro/thanks.php`, built by
copying `deliver.php`'s first three sections verbatim (config load, session_id regex validation,
Stripe verification, paid/complete check, expiry window). The web host gets its own signing key,
key id 2, so a compromised host costs only the keys it minted. Run `WardenKeyMint keygen` for it,
add the printed `[0x02]` line to `LicenseKey.PublicKeys`, and ship that build before the endpoint
goes live. Then instead of streaming a file:

```php
// openssl_sign() returns DER, SEQUENCE { INTEGER r, INTEGER s }; the client wants r||s, 32 bytes each.
function rww_p1363(string $der): string {
    $out = '';
    $o   = 2;                                         // a P-256 DER signature is < 128 bytes: 1-byte length
    for ($i = 0; $i < 2; $i++) {
        $len  = ord($der[$o + 1]);
        $out .= str_pad(ltrim(substr($der, $o + 2, $len), "\0"), 32, "\0", STR_PAD_LEFT);
        $o   += 2 + $len;
    }
    return $out;
}

// RFC 4648 base32 without padding: 75 bytes -> 120 characters.
function rww_base32(string $bin): string {
    $abc  = 'ABCDEFGHIJKLMNOPQRSTUVWXYZ234567';
    $bits = '';
    $out  = '';
    foreach (str_split($bin) as $c) $bits .= str_pad(decbin(ord($c)), 8, '0', STR_PAD_LEFT);
    foreach (str_split($bits, 5) as $b) $out .= $abc[bindec(str_pad($b, 5, '0'))];
    return $out;
}

// Idempotent: same session always returns the same key.
$issued = @json_decode(@file_get_contents($CFG['key_log']), true) ?: [];
if (isset($issued[$sessionId])) {
    $key = $issued[$sessionId];
} else {
    $pkey    = openssl_pkey_get_private(file_get_contents($CFG['warden_signing_key']));
    $payload = "\x02\x02\x01" . random_bytes(8);     // format v2, key id 2 (this host), Pro, 8-byte serial
    if (!$pkey || !openssl_sign('RWW-LICENSE-V2' . $payload, $der, $pkey, OPENSSL_ALGO_SHA256)) {
        http_response_code(500);
        exit('Key signing failed. Your payment went through; email support for your key.');
    }
    $key = 'WARD-' . implode('-', str_split(rww_base32($payload . rww_p1363($der)), 8));
    $issued[$sessionId] = $key;
    file_put_contents($CFG['key_log'], json_encode($issued), LOCK_EX);
}
```

Render the key large and copyable, with the download link and activation instructions on the same
page, and log `email`/`session`/`key` to the order log. The key carries its serial, which is what a
revocation would name; `WardenKeyMint verify <key>` prints it. `warden_signing_key` (the path to
the host's PEM) and `key_log` live in `/home/<user>/rs-delivery-config.php`, chmod 600, outside
`public_html`. The PEM sits outside `public_html` too, chmod 600. Anyone who can read it can mint
keys, which is one more reason manual stays the default until volume justifies the endpoint.

The idempotency check is the part people skip and then regret: without it, a buyer who refreshes
gets a second key and your issued-key list stops meaning anything.

Theme Studio uses the same HMAC scheme and has the same extractable secret. Before this endpoint can
serve it, Theme Studio needs its own key pair, its own context string (`RTS-LICENSE-V2`, say), and
the same client change.

### Step 13 — SmartScreen, honestly (included in Step 11's hours)

What actually happens: the zip is downloaded through a browser, so every file inside inherits
Mark-of-the-Web. On first run Windows shows a full-screen blue dialog, *"Windows protected your PC
— Microsoft Defender SmartScreen prevented an unrecognised app from starting."* The only visible
button is **Don't run**. The user has to click the small **More info** link and then **Run anyway**.
A meaningful fraction of buyers stop at that screen and email you instead, or ask for a refund.

Options:

| Option | Cost | Effect |
|---|---|---|
| Ship unsigned | $0 | Warning on every download until reputation accrues. Never accrues at low volume. |
| OV certificate | ~$200-400/yr | Names you as publisher. Does **not** clear SmartScreen immediately; reputation still has to build. Key must live on FIPS 140-2 hardware since June 2023, so add token or cloud-signing setup. |
| EV certificate | ~$400-700/yr | The only option that kills the warning on day one. |
| Azure Trusted Signing | ~$120/yr | Much cheaper, but requires a verifiable 3-year organisation history. Revenant Systems LLC probably does not qualify yet. Worth 20 minutes to check. |

**Recommendation: ship unsigned this round.** Put an honest, screenshotted "Windows will warn you,
here is exactly what to click" block on the download page and in the README, and publish the
SHA-256 so anyone who cares can verify the file. Revisit after the first ten sales. Do not spend
$500 on a certificate against $0 of revenue.

### Step 14 — Price (0.25 h to decide, bundled into Step 8)

Current ladder: $5 icon sets, $10 Theme Studio Pro, $19-24 skill packs, $149 bundle.

**Recommendation: $29, one-time, perpetual. Optional $19 launch price for the first 30 days.**

The reasoning:

- **Not a subscription.** Warden runs no service and includes no inference. Every recurring
  comparable (Cursor at $20/mo, Copilot at $10/mo) is charging for model access. Charging monthly
  for a BYO-key wrapper with no server cost is not defensible and buyers will say so.
- **Above the skill packs ($19-24).** Warden is a compiled Windows application with a support
  surface, not a folder of markdown.
- **Above Theme Studio ($10),** but that comparison cuts against you: RTS is the larger and more
  polished product. $29 for Warden next to $10 for RTS only holds if the Warden page is good. If
  the page is thin, the ladder looks arbitrary.
- **Below $49.** No signature, no screenshots yet, no reviews, no track record, and the Pro tier is
  three features, one of which wraps an MIT-licensed engine you publish for free. $49 invites
  scrutiny you cannot currently survive.
- $29 also means one refund does not sting, which matters while the SmartScreen and BYO-key
  frictions are unmeasured.

The $19 launch price is worth doing and worth explaining honestly: *"v1.0 launch price. The build is
not code-signed yet, so Windows will show a warning. Price goes to $29 when it is signed."* That is
credible, it converts, and it gives you a reason to email early buyers later.

## Part 4. Why shipping this week is a bad idea

Not "do not ship." These are the things that will bite, ranked.
